# 전투 애니메이션·카메라 설정 제출 기록 — 2026-09-30

`feat/BattleSystem`에서 `develop`으로 제출하는 누적 작업이다. 궁수의 상세 에셋·적용 방법은 [궁수 인계 문서](BOW_ANIMATION_HANDOFF_2026-09-30.md)를 먼저 참고한다.

## 원투 크로스헤어 보정

- 테스트 맵: `/Game/Levels/test_gm/UnarmedHooks/L_Test_UnarmedHooks`.
- 변경 시퀀스: `AN_HB_Unarmed_RightHook`, `AN_HB_Unarmed_LeftHook`. 두 독립 시퀀스/몽타주와 RightHook → LeftHook 순서는 유지한다.
- 머리 카메라 기준으로 공격 팔의 `upperarm/lowerarm/hand` 회전만 보정했다. 접촉 구간에서 주먹을 약 11cm 낮추고 4cm 앞으로 보내며, 팔 길이·스케일과 비공격 가드 손, 머리·몸통·하체 키는 유지한다.
- 보정 전 화면 중심선과 판정 선분의 최소 거리는 오른손 10.861cm / 왼손 10.920cm였다. 보정 후 기존 측정은 0도에서 0.252 / 0.093cm, -45도에서 0.031 / 0.109cm, +45도에서 0.018 / 0.105cm다. 타격 반경은 8cm이며, 이는 타격 구간 내 최소 거리이지 훅 전체를 화면 중앙에 고정했다는 뜻은 아니다.
- 자동 보정 스크립트나 과거 Blender 원본을 다시 임포트하면 현재 키를 덮어쓸 수 있다. 최종 엔진 시퀀스를 기준으로 이어서 작업한다.

## UHBSettingsWidget

- 대상: `Content/UI/Settings/WBP_Settings`, `Source/HeavenBreach/UI/Settings/HBSettingsWidget.cpp`.
- 조작 탭에 `Row_CameraMotion`, `Slider_CameraMotion`, `Text_CameraMotion`을 추가했다. 기존 감도 줄의 스타일을 따른다.
- 라벨은 **카메라 움직임**, 범위는 0~100%다. 툴팁은 “걷기와 공격 중 머리 움직임이 화면에 들어가는 정도입니다. 낮추면 흔들림이 줄어듭니다.”이며 설명란에도 표시된다.
- 기존 피격 시 전투 카메라 흔들림 토글과 별개다. 적용/저장/취소/기본값 처리와 선택 위젯 바인딩은 최신 `develop`의 설정 코드를 사용한다. 이번 PR의 C++ 차이는 조작 안내 문구 한 곳이다.
- 연동 클래스: 팀원의 `UHBSettingsSubsystem`, `UHBCameraMotionComponent`. 카메라 컴포넌트/플레이어 코드를 별도로 수정하지 않았다.
- 0%는 팀원 컴포넌트의 부드러운 추종 값을 사용한다. 카메라를 완전히 고정하거나 머리 움직임을 전부 없애는 옵션은 아니다.
- 확인 방법: 설정 → 조작 → 100% 적용 후 공격/걷기, 이어서 0% 적용 후 동일 동작 비교. 0% 적용 후 다시 열어 유지되는지, 미적용 변경을 취소하면 이전 값이 남는지 확인한다.

## 제출 검증과 한계

- Development Editor 빌드 성공. 설정 WBP, 활 캐릭터/컨트롤러/몸·시위 AnimBP, 마법 데모 플레이어 Blueprint 컴파일 완료.
- 마법 Demo 맵 PIE에서 `BP_FPPlayer_C` / `ABP_FPMeleeAnims_C` 실행을 확인했다. 플레이어 그래프의 직접 키 입력 10개와 마우스 축 2개, 제거된 레거시 InputAction 매핑을 확인했다. 가이드의 모든 물리 입력을 다시 눌러 검증한 것은 아니다.
- 실제 WBP의 100%/0% 적용 후 원투를 비교했다. 공격 중 카메라 회전 범위는 100%에서 약 1.607 / 4.406 / 6.750도, 0%에서 0.738 / 1.808 / 3.203도로 감소했다. 서로 다른 실행의 구간 측정값이며 모든 상황의 감소율을 보장하는 수치는 아니다. 테스트 후 100%로 복원했다.
- 최신 develop 통합 후 카메라 100%에서 다시 측정한 타격 구간 최소 거리(cm): 피치 0도 RightHook 0.0979 / LeftHook 0.1072, -45도 0.0006 / 0.1091, +45도 0.0442 / 0.1036. 모두 기존 판정 반경 안에서 중심선을 지나갔다.
- 2인 리슨서버 원투 검사에서 서버와 소유 클라이언트의 RightHook → LeftHook 재생, 중복 예약 처리, 종료 후 초기화를 관측했다. 70cm 거리에서 단타·원투·다음 단타 총 4회 피해로 HP 195 → 146.8519를 확인했다.
- 자동 원투 검사는 다음 월드 tick의 서버 컨트롤러 이벤트 호출이다. 실제 하드웨어 클릭이나 클라이언트 RPC 왕복까지 검증한 결과로 해석하지 않는다.
- 궁수는 2인 리슨서버에서 AA/AC의 장전 유지·놓기·상하 조준·웅크리기·이동·짧은 클릭 등 10개 조건을 재검사했다. 335개 표본과 양쪽 월드의 네 캐릭터를 관측했으며 검사 오류는 없었다. 완전 장전 구간의 248개 관측에서 시위 접점 오차는 부동소수점 수준, 화살 깃 오차는 최대 약 0.00004cm였다. 화살촉 정렬 계산은 기본 조준 회전을 기준으로 하며 모든 카메라 흔들림 설정의 실제 화면 정렬까지 보장하지 않는다. AN은 AC 모션 fallback이며 동일 수준의 전용 모션 검증 대상이 아니다.
- 활 투사체는 표시·경로 확인용이다. 실전 피해/GAS/탄약/인벤토리 연동과 late join 상태 복구는 별도 구현이 필요하다.
- 시작 로그의 기존 `FSkillCardData` 미초기화, `IA_Interact` null trigger, 테스트 시작 직업/loadout 불일치 메시지는 이번 변경과 별도로 남아 있다. 해당 소유 클래스·입력 에셋은 이번 PR에서 수정하지 않았다.
- raw 측정·그래프·스크린샷은 로컬 `Saved/PR_20260930/`에 보관하며 저장소에 커밋하지 않는다.
