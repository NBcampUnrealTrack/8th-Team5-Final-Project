# 계층 규칙과 사용자 지정 포탈

## 실게임 랜덤 포탈: LD 설정

1. 원본 방 레벨에 `HB Portal Spawn Point`를 원하는 만큼 배치한다.
   포인트는 **바닥에 놓고**, Scale은 `(1, 1, 1)`을 유지한다. 회전으로 포탈 방향을 정한다.
   `Point Id`는 같은 원본 레벨 안에서 중복되지 않게 지정한다.
   다른 레벨에서 같은 ID를 쓰거나 같은 방을 여러 번 생성해도 방 인스턴스 ID로 구분한다.
2. 포탈 BP의 `Trigger` 크기와 `Arrival`의 상대 XY 위치·방향을 설정한다.
   Arrival은 Trigger 밖의 빈 바닥 쪽으로 둔다. 원본 방에 포탈 액터나 상대 포탈 참조를 배치할 필요는 없다.
3. 게임 맵의 `HB Dungeon Runtime` 또는 그 파생 BP에서
   `Portal Placement Mode = Random Points`, `Portal Class = 사용할 포탈 BP`,
   `Portal Pair Count = N`을 설정한다. 포탈 BP는 `Replicates`를 끈 클래스를 사용한다.
   기존 `Floor 1 Exit`, `Floor 2 Entry`, `Boss Corridor`는 방 구성에 계속 필요하다.
   Random Points에서는 고정 포탈 ID 선택이 필요 없다.
4. **실제 생성될 각 논리 계층**에 유효한 후보가 최소 N개 있어야 한다.
   등록된 전체 원본 맵의 포인트 합계가 아니라 이번에 선택된 방 인스턴스의 합계다.
   벽·천장·문 차단벽, 다른 포탈의 진입·도착 공간과 겹친 후보는 제외하므로 여분을 둔다.
5. `Validate Module`로 포인트 ID와 Scale을 검사한 뒤 저장하고 생성한다.
   READY를 확인하고 실제 플레이어로 진입과 왕복 이동을 확인한다.

PCG가 1계층 후보와 2계층 후보에서 중복 없이 선택해 N쌍을 만든다.
LD는 짝을 지정하지 않는다. 논리적 계층은 `Room Info / Allowed Floor`와 생성된 방의 Floor로
결정하며, 단순히 월드 높이가 다른지를 기준으로 삼지 않는다.

생성 시 실제 포탈 Trigger의 바닥을 포인트 아래 바닥에서 2cm 위로 맞춘다.
도착점은 BP의 상대 XY와 방향을 유지하고, 그 위치의 바닥 위에 실제 기본 플레이어 캡슐의
반높이 + 2cm만큼 올린다. 따라서 포인트나 Arrival의 높이를 캐릭터 반높이에 맞춰 띄울 필요가 없다.
바닥이 없거나 캡슐이 벽에 겹치는 후보는 제외한다. 옆이나 다른 층으로 도착 위치를 탐색하지 않는다.
포탈에는 NavMesh 경로 검사를 적용하지 않는다. 포탈의 진입·도착 공간은 몬스터와 상자의
배치에서 제외한다. 플레이어가 포탈까지 걸어갈 수 있는지는 LD가 실제 플레이로 확인한다.

## 멀티플레이 동작과 검증

실게임 Runtime의 Standalone과 Listen 서버에서 사용할 수 있다.
서버가 방을 로딩하고 포탈을 최종 선택한 뒤, 같은 생성 번호의 GameState 스냅샷에
방 ID·포인트 ID·짝·액터/Trigger/Arrival 위치와 예약 공간을 기록한다.
클라이언트는 이 결과로 로컬 포탈을 복원한다. 별도 추첨이나 바닥/NavMesh 재검사를 하지 않는다.
포탈 결과를 받고 방과 포탈을 모두 준비한 뒤에만 READY와 로딩 완료를 서버에 보고한다.
실제 순간이동과 재진입 제한은 서버가 처리한다.

늦게 접속한 클라이언트도 보관된 최종 결과를 받는다. 매치 시작 전 `Regenerate Dungeon`을
실행하면 이전 생성의 포탈과 연결을 정리하고 새 생성 번호의 결과를 배포한다.
PIE는 `Net Mode = Play As Listen Server`, `Number of Players = 2` 이상으로 검증한다.
Dedicated Server 생성은 현재 Runtime의 지원 범위가 아니다.

자동화 `HeavenBreach.PCGModule.Network.RandomPortals`는 임시 방과 실제 IP 연결로
서버·클라이언트의 쌍/위치 일치, 원격 플레이어 왕복 이동, 늦은 접속,
매치 시작 전 재생성 및 정리를 검사한다. 프로젝트 레벨 에셋을 덮어쓰지 않는다.
`HeavenBreach.PCGModule.PortalRuntime.Snapshot`은 최종 데이터 검증,
같은 생성 번호의 추가 업데이트, 중복 적용, 복원 실패 시 전체 정리를 검사한다.

## 고정 포탈과 Preview 에디터 설정

Generator의 Details는 `PCG Preview - Modules`, `PCG Preview - Exploration`처럼
독립된 카테고리로 표시한다. Exploration에는 시작 모드와 감도만 있으며,
현재 탐색 여부와 방 번호는 Result, 탐색 Pawn 참조는 Debug에서 확인한다.
PCG·카메라 컴포넌트 참조는 액터 설정에 반복 표시하지 않는다.

1. 각 방 레벨의 `HB Dungeon Module Definition` → `Room Info`에서 `Room Role`과
   `Allowed Floor`를 설정한다. `Any / Floor1 / Floor2`는 논리적 진행 계층이며 월드 Z 좌표가 아니다.
   보스방은 생성 시 항상 2계층이다. 보스방을 `Floor1` 전용으로 설정하면 검증에 실패한다.
2. 계층 전환에 쓸 두 방 레벨에 `HB Dungeon Portal` 액터를 **직접 배치**한다.
   각 방 안에서 유일한 `Portal Id`를 지정한다. 액터의 `Trigger` 박스는 진입 영역이며,
   `Arrival` 화살표는 이 포탈로 도착하는 Pawn의 원점과 바라보는 방향이다.
   Arrival은 Trigger 밖, 플레이어 캡슐이 들어갈 수 있는 빈 공간에 놓는다.
   트리거 크기는 액터 Scale이 아니라 Box Extent로 조절한다.
3. 보스 직전 복도 레벨에도 모듈 정의, 문 커넥터 두 개 이상, 점유 박스를 배치한다.
   `Module Kind = Corridor`로 설정한다. Room Role은 복도에서 사용하지 않는다.
   기존 `passage` 레벨을 선택할 수 있지만 어떤 이름도 코드에 고정되어 있지 않다.
4. 각 레벨에서 `Validate Module`을 실행하고 저장한다.
5. Generator의 `Module Maps`에 방과 복도 레벨을 한 번씩 등록한다.
   방/복도 구분은 각 레벨의 `Module Kind`에서 읽는다. 기존 등록 목록과 전환 맵 설정은
   처음 로드할 때 통합 목록으로 이전된다. 이후 목록에서 삭제한 맵은 자동 재등록하지 않는다.
6. `Use Dungeon Rules`를 켜고 `Transitions`에서 등록한 맵을 선택한다.
   - `Floor 1 Exit`, `Floor 2 Entry`: 사용자가 정한 1계층 출발방과 2계층 시작방.
   - 각 `Portal`: 직접 배치한 포탈을 액터 이름으로 선택한다. 포탈이 하나면 자동 사용하고,
     여러 개면 드롭다운에서 선택한다. 없으면 원본 레벨에 포탈을 배치해야 한다.
     Generator에 ID를 복사할 필요는 없지만 포탈 액터에는 고유한 `Portal Id`가 필요하다.
     이전에 선택한 ID가 사라지면 자동 대체하지 않고 오류를 내므로 다시 선택해야 한다.
   - `Boss Corridor`: 보스 직전에 배치할 등록된 복도 레벨.
   - `Floor2 Offset`: Generator 기준 2계층 시작방의 위치. 두 구역이 겹치지 않게 설정한다.
     같은 높이에 떨어뜨려 배치해도 된다.
7. `Room Counts`의 `Floor1/2 Main Rooms`는 메인 경로의 방 수다. 시작·전환·보스방은
   포함하고 복도는 제외한다. `Floor1/2 Branch Rooms`는 선택 경로의 방 수이며
   2계층 분기가 1계층보다 많아야 한다. 합계도 표시한다.
   규칙 모드를 끄면 연결 테스트용 `Test Room Count`만 표시한다.
8. 재사용·탐색 횟수·시간은 두 모드의 공통 `Search` 설정이다.
   `Refresh Module Catalog` 후 one-player PIE로 실행한다. 카탈로그/오류는 `Debug`,
   실행 결과는 `Result`에서 확인한다. 전환 맵 누락 등은 명시적인 오류로 중단한다.
   Generator의 Seed와 `Advanced`의 Graph가 생성에 사용되며 PCG 컴포넌트 값은 생성 시 덮어쓴다.

포탈은 상대 액터를 원본 레벨에서 직접 참조하지 않는다. 생성기가 방 인스턴스 ID와 Portal Id로
해당 스트리밍 레벨 안의 액터를 찾아 양쪽을 연결한다. 따라서 동일한 원본 맵을 여러 번 사용해도
다른 인스턴스의 포탈로 잘못 연결되지 않는다. 전환방은 지정된 위치에만 배치된다.

## 생성과 검증

기본 경로는 `1계층 시작 → 지정 출발방 → 포탈 → 지정 2계층 시작방 → 모험방 → 지정 복도 → 보스방`이다.
중간 방 수와 실제 모듈·문 선택은 시드 및 탐색 결과에 따라 달라진다. 물리적 연결은 커넥터 정렬과
점유 OBB 겹침 검사로 결정한다. 포탈 연결에는 문 위치를 서로 일치시키는 검사를 적용하지 않는다.

- 시작방은 1계층 모험방. 보스방은 전체에서 정확히 하나이며 2계층 메인 경로의 끝이다.
- 보스방 바로 앞에는 선택한 복도가 하나 있으며, 복도 바로 앞에는 모험방이 있다.
  2계층 도착방 다음에 곧바로 보스 복도를 붙이지 않는다. 복도에는 추가 분기를 붙이지 않는다.
- 회복방·강화방은 계층별 최대 하나. 시작방 바로 다음이나 같은 특수 역할 뒤에는 놓지 않는다.
- 모험방은 같은 계층에서 최대 세 개 연속. 포탈을 통해 다른 계층으로 넘어가면
  이전 계층의 연속 횟수를 0으로 초기화한다. 도착방이 모험방이면 새 계층의 첫 번째로 센다.
  복도는 방 역할 개수에서 제외하며 모험방 연속 횟수를 초기화하지 않는다.
- 모험방은 다른 각 역할보다 많아야 한다. 강화방은 선택 분기에 우선 배치하되, 유효한 배치가
  없으면 메인 경로에서도 사용할 수 있다. 현재 선택 분기는 메인 경로에 붙는 말단 방이다.
- 논리적 전환방 연결은 한 쌍이며, Fixed 모드의 포탈도 한 쌍이다. 실게임 Random Points의
  포탈 수는 `Portal Pair Count`로 정한다. 2계층 분기 방 수가 더 많으며, 방 내부의 계단·다리·고저차는
  레벨 제작자가 구성한다. 이 생성기가 방 내부 지형을 변경하지는 않는다.
- 포탈 액터 누락, ID 중복, 잘못된 계층·복도 선택, 점유 겹침, 불가능한 방 구성은 실패한다.
  실패한 후보는 백트래킹하며 탐색 횟수·시간 제한에 도달하면 부분 결과 없이 오류를 반환한다.
- 로딩 후 실제 포탈 액터와 카탈로그의 위치·크기를 재검증하고 쌍방 연결을 확인해야 READY가 된다.
- 포탈은 플레이어 Pawn의 원점이 Trigger 안에 들어오면 작동한다. 충돌 없는 미리보기 Pawn도
  지원한다. 플레이어별로 재진입 대기와 트리거 이탈을 요구해 즉시 왕복을 막는다.
  일반 Pawn의 지정 도착 위치에 충돌이 있으면 이동을 거부한다. 빈 공간인지 확인한 뒤
  TeleportTo를 실행하며, 벽 반대편의 임의 위치를 도착점으로 대체하지 않는다.

문 정렬, 그래프 도달 가능성, 점유 검사는 방 내부의 실제 보행 경로나 NavMesh 연결성을 증명하지 않는다.
문이 벽으로 막혀 있지 않은지, 포탈까지 도달할 수 있는지, 도착 지점의 캡슐 여유 공간은 실제
플레이 캐릭터로 확인해야 한다. 회복방의 플레이어별 1회 사용, 전투·파밍은 각 방의 게임플레이 기능이다.
Preview의 Standalone/one-player 제한은 유지한다. 실게임 Runtime의 네트워크 포탈 동작은 위 항목을 따른다.

## 테스트 및 이전 연결 테스트

`HeavenBreach.PCGModule.Rules`는 여러 시드 생성·재현, 계층·역할 규칙과 잘못된 설정 거부를 검사한다.
`HeavenBreach.PCGModule.Portal`은 원본 맵 포탈 검증, 쌍방 연결, 실제 Pawn 이동과 재진입 방지를 검사한다.
기존 `HeavenBreach.PCGModule.Direct*` 테스트는 문 정렬과 점유 검사에 계속 사용한다.

`Use Dungeon Rules = false`는 기존의 규칙 없는 LD 연결 테스트를 명시적으로 선택한다.
이때만 `Test Room Count`를 사용하고 계층 전환·보스 복도를 생성하지 않는다.
기존 `HBDungeonLayout` 격자 프로토타입은 현재 규칙 생성기의 실행 경로가 아니다.
